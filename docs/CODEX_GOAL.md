# Codex `/goal` 持续开发提示词

下面是本仓库的长期目标提示词。它定义“怎么持续开发”，具体任务范围永远以 `config/goal-state.json` 中唯一的 `nextSlice` 为准。

## 可直接交给 Codex 的目标

> 持续把 Asset Delivery Organizer 开发成面向国内技术美术团队的生产级中文资产交付工作台。优先解决真实交付中的项目规则配置、文件事实检查、问题证据、安全整理、复检与追踪，不为了展示复杂度引入无必要的 Agent、云服务或多 DCC 壳层。
>
> 每轮开始必须读取 `AGENTS.md`、`config/goal-state.json`、其 `lastCheckpoint`、Git 状态以及当前切片相关代码和测试，并运行固定入口 `scripts/goal.ps1 -Action Resume` 与 `-Action Doctor`。状态与代码冲突时先修复事实源。
>
> 一次只实现 `nextSlice`，只修改 `allowedPaths`，遵守 `nonGoals`。先证明用户、输入、输出、写入状态、黄金路径和最重要失败路径，再实现最小完整闭环。业务核心与 PySide6 界面分离，成功、失败、边界和恢复必须自动化验证。
>
> 审计永远只读。整理必须经过 dry-run 计划、路径与哈希预检、冲突阻断、明确批准、失败回滚、外部收据和执行后复检。不得静默覆盖、删除输入或修改不可变演示夹具。
>
> 界面、README、教程和截图以自然简体中文为主。每个展示版本都要提供许可证清晰的公开素材或可重复生成的合成素材，并覆盖成功、错误/阻断、批量/边界和处理前后对比。截图必须来自真实程序运行；桌面发布必须完成不抢焦点、精确 PID 隔离的 Windows Qt 生命周期验证。
>
> 只有当前切片所有 acceptance 都有直接证据，固定验证全部通过，才允许增加 `stateRevision`、写入顺序 checkpoint 并推进下一个切片。不要把计划、Mock、导入成功或理论可行写成已完成。遇到失败先诊断和安全降级；只有同一不可绕过条件持续存在时才标记 blocked，并写明恢复条件。

## 每轮决策顺序

1. **事实正确**：代码、状态、测试、文档和截图不能互相矛盾。
2. **用户价值**：优先减少真实审核人员的重复选择、漏检和危险手工整理。
3. **数据安全**：任何写操作都必须可预览、可阻断、可恢复、可复检。
4. **可解释性**：问题必须能追溯到文件、规则、观测值、期望值和建议。
5. **可复现证据**：测试、素材、截图、教程和干净安装共同证明能力。
6. **架构克制**：只为已经出现的变化点建立抽象，不为“显得复杂”预造平台。
