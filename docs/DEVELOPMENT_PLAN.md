# 开发计划

## 产品边界

工具首先回答“这批交付里有什么、是否符合项目规则、缺什么、哪些旧版本仍在”。核心无 DCC 依赖，规则由版本化 Profile 驱动，报告可被 Art Pipeline Skill、通用 Agent、CI 或其他生产工具消费。

## 已完成：M0 只读审计 MVP

- 严格兼容 `art-delivery-profile/1` 和 `art-delivery-audit-report/1`；
- 递归扫描、SHA-256、稳定相对路径、媒体类型和命名 token；
- `filename.pattern`、`texture.required-channels`、`version.latest-only`；
- stdout/外部文件 JSON 输出、稳定 audit identity、固定退出码；
- 输入目录写入防线、路径穿越防线、符号链接边界；
- 有效、错误、重复版本、缺失贴图和只读回归测试。

## 已完成：M1 互操作与规模化

1. ✅ 已将 Skill 导出的 Profile/Report Schema 加入可重复的合同一致性门禁，且运行时不依赖兄弟仓库；
2. ✅ 已明确大小写/Unicode 规范化碰撞、不可读文件和扫描中途变化的失败关闭语义；
   同时为文件数量、单文件大小和交付总大小提供默认预算与 CLI 覆盖，限制失败发生在内容哈希前；
3. ✅ 已按稳定 `audit_id` 提供 artifact 路径，并逐字段/数组元素流式序列化标准报告；外部文件采用同目录临时文件和原子替换；
4. ✅ 已提供机器可读的合同/规则/安全/限制能力清单和带环境信息的可重复性能基线。

M1 保持只读，没有增加 UI、文件整理或 DCC 逻辑。发布级完成证据见 `docs/RELEASE_AUDIT_2026-08-25.md`。

## 后续候选：安全整理计划

本路线已在 M4 获得授权并实现。任何执行必须同时具备：

- dry-run 预览；
- 路径与大小写冲突检测；
- 明确人工批准；
- 不静默覆盖；
- 内容哈希与执行收据；
- 执行后复检与可恢复策略。

材质网络、Maya 操作和其他 DCC Adapter 不属于该阶段，必须由独立需求证明其必要性。
